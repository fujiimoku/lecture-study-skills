# 输出与构建

## Markdown

- 保存 `.md`，标题层级清晰；主要章节用短概述加条目，重要词首次加粗，中英术语首次对照。
- 数学用 `$...$` / `$$...$$`，代码块注明语言，表格用于对比；渲染支持取决于阅读器，不能保证所有阅读器都显示数学或 Mermaid。
- 引用如 `[课件A, PDF p12–13]`。重点标签图例放在文首。
- 重新读取已保存文件，核查末尾是否完整、表格/代码围栏是否闭合、公式是否丢失，并对照覆盖表。不要用文件大小替代覆盖性检查。

## LaTeX 与 PDF

- 若宿主提供内置 LaTeX 编辑器，优先保存并打开 `.tex`，使用内置编译器诊断；遵循其单文件、资源和重试限制。内置编译可用时，不因系统找不到 `xelatex` 就认定无法编译，也不自行安装 TeX。
- 区分“编译/预览成功”和“PDF 已导出到磁盘”：只有确认实际导出文件存在且对应当前源文件，才提供 PDF 下载链接。编辑器不支持导出时保留源文件，说明 PDF 导出尚未完成；需要独立 PDF 时检查可用的本地构建路径。
- 本地编译选用实际可用且支持当前中文字体和宏包的引擎；通常使用 XeLaTeX/ctex。仅加载必要宏包，先确认环境支持，不能声称固定白名单能保证编译成功。
- 在独立构建目录运行，保留日志；路径使用平台原生引用方式，不写死 `/tmp` 或 Bash 命令。不要开启 shell escape。使用非交互、遇错退出选项；交叉引用需要时再编译一轮。
- 单栏排版、正常字号和页边距。转义普通文本中的 `% & _ #` 等字符；数学保持数学模式。重点符号缺字时改用“必背/理解/易错”等文字，不假设某种字体一定覆盖所有 Unicode 符号。
- 只有当前构建成功且无致命错误，才能交付当前 PDF；旧 PDF 存在不代表新源文件构建成功。
- 检查渲染后的页面，尤其中文、数学密集页、长表、图示和末页；查找溢出、裁切和缺字。未能视觉检查时明确说明未验证的项目。
- 没有可用编译/导出能力时继续保存源文件与已核查内容，说明所需 PDF 未完成。不能未经用户同意把其他格式宣称为等价完成。
