# 图解算法与过程例题

用于把图、伪代码、队列变化或逐帧课件整理成可重做的过程。遵循原课程的算法版本，不把某一学科的术语套到其他课程。

## 从页面重建过程

1. 直接查看图页及相邻的连续过程页，记录输入、边方向、权重、初始状态及算法规则。无法确认的图中细节局部标记待核对，不根据常见题型猜图。
2. 明确每步记录的是扩展前还是扩展后。使用紧凑表格或编号步骤记录“本步选择、关键计算、更新后的状态、选择原因”。只展示对解释有作用的字段。
3. 对搜索类例题，把 frontier 中的项记录为路径或可区分的节点实例，区分节点状态、路径代价 g、启发值 h 与排序值。说明目标测试发生在生成/入队还是取出时，以及遇到更短路径是否更新、是否重开已扩展状态。
4. 相同优先级没有指定顺序时，说明可有多种合法顺序。需要选定一种才能展示时，显式列为补充约定；使用栈时区分孩子生成顺序、入栈顺序和弹出顺序。
5. 保留原例结果。为解释规则另造小例子时标为补充示例，不给它伪造原课件页码；只引用其解释的概念来源。

## 性质与核查

- 把正确性、完备性和最优性结论与所需前提绑定。不要把出队终止单独当作所有启发式或所有图搜索实现的最优性保证。
- 对有限/无限状态空间、有限分支、等步代价/非负代价/正下界、可采纳性/一致性及重复检测等，只补充当前结论所需的条件，并区分课件明确内容与补充说明。
- 重新计算累计代价、关键优先级及最终结果，检查过程是否真的遵循所述规则。无法可靠复算时保留可确认部分和具体疑点，不宣称已经验证。
- 过程较长时保留关键转折并交代省略范围；不要声称展示了每一步却只列起点和答案。
